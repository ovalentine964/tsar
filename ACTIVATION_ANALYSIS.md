# TSAR Activation Analysis — Complete Execution Flow & Blockers

## 1. STARTUP FLOW (from `src/__main__.py`)

When `python3 -m src --paper` runs, the execution path is:

```
main()
  → parse_args()
  → _validate_secrets()          ← BLOCKS if TSAR_API_KEY missing/weak
  → asyncio.run(run_full_system(args))
      → load_config("config/tsar.yaml")
      → setup_logging()
      → get_backend_registry()._register_defaults()
      → Initialize Knowledge Stores (TradeMemory, PatternLibrary, etc.)
      → Initialize Risk Components (GuardState, KillSwitch, Watchdog)
      → Create Event Bus (shared singleton — in-memory or Redis)
      → Initialize Engines via Registry:
          - exchange_gateway → CcxtGateway (needs EXCHANGE_API_KEY)
          - execution_engine → PaperExecutionEngine (paper mode)
          - pricing_engine → PandasTAEngine
          - risk_engine → PythonRiskEngine
          - llm_provider → OpenAIProvider (NVIDIA NIM)
      → Create All 13 Agents
      → Wire agents to shared resources
      → Start Watchdog (heartbeat monitor)
      → Start API server (background task)
      → Start heartbeat writer
      → Start agent health monitor
      → Start Telegram bot (if token configured)
      → await orchestrator.start()  ← THIS IS THE MAIN LOOP
          → orchestrator.on_initialize()
              → _load_agent_registry()
              → For each enabled agent:
                  agent = _create_agent(name, publisher, subscriber)
                  await agent.start()  ← Each agent:
                      → on_initialize() (connect to exchange, etc.)
                      → Start stream subscriptions
                      → Start _main_loop() (calls run_cycle() every ~1s)
              → _initialize_orchestrator_tools()
              → _initialize_shadow_loop()
```

## 2. STRATEGY REGISTRATION

Strategies are loaded from **YAML config files**, NOT a database or API:

- `config/strategies/mean_reversion.yaml` — Default strategy genome
- `config/strategies/momentum.yaml` — Momentum strategy
- `config/tsar.yaml` → `strategies.mean_reversion.params` — Runtime params

The SignalScout agent reads strategy params in `__init__()`:
```python
strategy_config = config.get("strategies", {}).get("mean_reversion", {})
self._params = {**self.DEFAULT_PARAMS, **strategy_config.get("params", {})}
```

**No explicit "strategy registration" step is needed** — the strategy is baked into SignalScout's code and config. The StrategyGeneticist can mutate parameters at runtime via events.

## 3. AGENT LIFECYCLE & DATA FLOW

### Event Pipeline (Event-Driven, not polling):

```
SignalScout (every 5 min)
  ↓ publishes "tsar.signal.detected.v1" to "signals" stream
  ↓
RiskGuardian (subscribes to "signals")
  ↓ evaluates 10-point checklist
  ↓ publishes "tsar.risk.approved.v1" to "risk_decisions" stream
  ↓
ExecutionSniper (subscribes to "risk_decisions")
  ↓ places stop-loss FIRST, then entry order
  ↓ publishes "tsar.trade.executed.v1" to "trades" stream
  ↓
TradePhilosopher (subscribes to "trades")
  ↓ post-trade reflection
```

### Market Data Source:
- **CcxtGateway** → Binance REST API (via ccxt library)
- Fetches OHLCV candles: `await self._gateway.get_ohlcv(symbol, Timeframe.H1, limit=100)`
- Symbols configured in `config/tsar.yaml`: `["BTC/USDT", "ETH/USDT"]`

### Communication:
- **In-memory event bus** (default, no Redis needed for Day1)
- **Redis Streams** (optional, for production scaling)
- CloudEvents v1.0 format

## 4. BLOCKERS — Why TSAR Is Not Trading on Render

### 🔴 BLOCKER 1: Dockerfile CMD Only Starts API, NOT Trading System

**The Dockerfile runs:**
```dockerfile
CMD ["python", "-m", "uvicorn", "src.api.app:app", "--host", "0.0.0.0", "--port", "8000"]
```

**This ONLY starts the FastAPI server.** It does NOT start the trading agents.

The trading system requires: `python3 -m src --paper`

**FIX:** Change the Dockerfile CMD to:
```dockerfile
CMD ["python", "-m", "src", "--paper", "--host", "0.0.0.0", "--port", "8000"]
```

### 🔴 BLOCKER 2: Missing Environment Variables (Secrets Not Set)

The `render.yaml` has `sync: false` for critical env vars, meaning they must be manually set in Render dashboard:

```yaml
- key: NVIDIA_API_KEY
  sync: false          # ← Must be set manually
- key: EXCHANGE_API_KEY
  sync: false          # ← Must be set manually
- key: EXCHANGE_SECRET
  sync: false          # ← Must be set manually
```

**Required env vars:**
| Variable | Status | How to Get |
|----------|--------|------------|
| `TSAR_API_KEY` | Auto-generated by Render | ✅ Done |
| `EXCHANGE_API_KEY` | ❌ NOT SET | Binance testnet: https://testnet.binance.vision |
| `EXCHANGE_SECRET` | ❌ NOT SET | Same as above |
| `NVIDIA_API_KEY` | ❌ NOT SET | https://build.nvidia.com → Get API Key |
| `REDIS_PASSWORD` | Not needed | In-memory bus works without Redis |

### 🔴 BLOCKER 3: `_validate_secrets()` Will Crash on Startup

In `__main__.py`, the secret validator checks:
```python
api_key = os.environ.get("TSAR_API_KEY", "").strip()
if not api_key:
    errors.append("TSAR_API_KEY is empty...")
```

If `TSAR_API_KEY` is empty or uses a weak default, the process **exits with code 1** before ANY initialization.

### 🟡 BLOCKER 4: No `data/` or `logs/` Directories

The Dockerfile creates them (`RUN mkdir -p /app/data /app/logs`), but if running locally they don't exist. The code does `Path("data").mkdir(exist_ok=True)` so this is handled at runtime.

### 🟡 BLOCKER 5: Exchange Gateway Connection Failure

Even with API keys set, the CcxtGateway needs:
1. Valid Binance testnet API key/secret
2. Network access to `testnet.binance.vision`
3. The `EXCHANGE_SANDBOX=true` env var (set in render.yaml)

If the gateway fails to connect, SignalScout will log errors but continue running (it catches exceptions in `_scan_symbol`).

### 🟡 BLOCKER 6: LLM Provider (NVIDIA NIM) May Fail

The OpenAIProvider tries to connect to `https://integrate.api.nvidia.com/v1`. If `NVIDIA_API_KEY` is not set, LLM calls will fail. However, SignalScout has a **graceful fallback** — after 3 LLM failures, it switches to "pure statistical mode" and continues generating signals without LLM enhancement.

## 5. SIGNAL GENERATION CONDITIONS

For a trade to actually happen, ALL of these must be true simultaneously:

1. **RSI(14) < 30** (oversold) at a **support level** within 2% → BUY signal
   OR **RSI(14) > 70** (overbought) at a **resistance level** within 2% → SELL signal
2. **Signal score ≥ 0.6** (weighted: RSI 30% + S/R 25% + MTF 25% + Volume 10% + Trend 10%)
3. **Pullback confirmation** — price must have bounced 0.3% from recent low/high
4. **Volume confirmation** — 2 consecutive candles above 1.5x average volume
5. **Risk Guardian approves** — all 10 risk checks pass
6. **No kill switch active**, no circuit breaker RED
7. **Session timing** — entry allowed during active trading sessions
8. **No news blackout** — no high-impact events within proximity

**This is a MEAN REVERSION strategy — it only trades when RSI is extreme AND price is near S/R. In calm markets, it may sit idle for hours.**
