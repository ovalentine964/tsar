# TSAR — Connection Guide: Flutter App → Render Backend → Binance

## Architecture Overview

```
┌─────────────────┐       HTTPS/WSS        ┌──────────────────────┐       HTTPS        ┌──────────────┐
│  Flutter Mobile  │ ──────────────────────→ │   Render Backend     │ ──────────────────→ │   Binance    │
│  App (Android)   │  Bearer TSAR_API_KEY   │   (FastAPI + Agents) │  EXCHANGE_API_KEY  │   API        │
│                  │                         │   Dockerfile.trading │  EXCHANGE_SECRET   │  (Testnet/   │
│  Base URL:       │  ←── JSON responses ── │   Port 8000          │  ←── Market data ──│   Live)      │
│  Settings Screen │                         │                      │  ←── Orders ──────│              │
└─────────────────┘                         └──────────────────────┘                    └──────────────┘
```

**Key files:**
- Flutter API client: `mobile/lib/services/api_service.dart`
- Flutter settings: `mobile/lib/providers/settings_provider.dart`
- Flutter settings screen: `mobile/lib/screens/settings_screen.dart`
- Backend API: `src/api/app.py`
- Backend routes: `src/api/routes/` (health, trading, portfolio)
- Render deploy config: `render.yaml`
- Docker (trading): `Dockerfile.trading`
- Env template: `.env.example`

## Step 1: Get Binance Testnet API Keys

1. Go to **https://testnet.binance.vision**
2. Log in with your GitHub account
3. Click **"API Key"** → **"Generate HMAC_SHA256 Key"**
4. Copy both values:
   - **API Key** (looks like: `a1b2c3d4e5f6...`)
   - **Secret Key** (looks like: `x7y8z9w0...`)
5. ⚠️ **Save them immediately** — the secret is shown only once

> Testnet gives you virtual funds. No real money at risk.

---

## Step 2: Set Environment Variables in Render Dashboard

1. Go to **https://dashboard.render.com**
2. Select your **tsar-trading** service (created from `render.yaml`)
3. Go to **Environment** tab
4. Set these variables:

| Variable | Value | Notes |
|----------|-------|-------|
| `EXCHANGE_API_KEY` | *(your testnet API key)* | From Step 1 |
| `EXCHANGE_SECRET` | *(your testnet secret)* | From Step 1 |
| `EXCHANGE_SANDBOX` | `true` | **Must be `true` for testnet** |
| `TSAR_API_KEY` | *(auto-generated by Render)* | Copy this — you'll need it for the app |
| `NVIDIA_API_KEY` | *(your NVIDIA NIM key)* | Optional, for AI agents |

5. **Also set `TSAR_CORS_ORIGINS`** to `*` (allows all origins) for mobile app access
6. Click **Save Changes** → Render will redeploy automatically
7. Wait for the deploy to succeed (check **Logs** tab)

> `TSAR_API_KEY` is auto-generated in `render.yaml`. Find it in the Environment tab after first deploy.

## Step 4: Enter Render URL + TSAR_API_KEY in App

1. Open the TSAR app on your phone
2. Tap **"More"** → **"Settings"** (bottom navigation bar)
3. In the **API CONNECTION** section:
   - **Base URL**: Enter your Render URL
     ```
     https://tsar-trading.onrender.com
     ```
     > Find the exact URL in Render Dashboard → your service → "URL" at the top
     > ⚠️ The app defaults to `https://tsar-api.onrender.com` — update it to match your actual Render service URL
   - **API Key**: Paste the `TSAR_API_KEY` from Render's Environment tab
4. Tap **"SAVE & CONNECT"**
5. The green dot in the top-right should light up (WebSocket connected)

### Verify connection
- Go to **Dashboard** tab — you should see system status
- If you see "Disconnected" (red dot), check:
  - URL is correct (no trailing slash)
  - API key matches `TSAR_API_KEY` in Render
  - Render service is running (check Logs)

## Step 5: Enter Binance Keys

Binance keys are configured **server-side** (in Render), not in the app. The app talks to the Render backend, which talks to Binance.

### Option A: Render Environment (Recommended)
Set `EXCHANGE_API_KEY` and `EXCHANGE_SECRET` in Render Dashboard (Step 2 above).

### Option B: Direct in Render env
If you want to change keys without redeploying:
1. Update the env vars in Render Dashboard
2. Render auto-redeploys on env change

> **Security**: Binance keys never leave the server. The mobile app only uses `TSAR_API_KEY` to authenticate with the backend.

## Step 6: Switch Between Testnet and Live

### Testnet (safe, virtual money)
In Render Dashboard, set:
```
EXCHANGE_SANDBOX=true
TSAR_TRADING_MODE=paper
```

### Live trading (real money — requires mandate)
1. First, complete paper trading gate:
   - Check progress: App → Settings → Mandate → view gate status
   - Or: `curl -H "Authorization: Bearer $TSAR_API_KEY" https://your-url.onrender.com/api/v1/paper/gate`
2. Set in Render Dashboard:
   ```
   EXCHANGE_SANDBOX=false
   TSAR_TRADING_MODE=live
   ```
3. Generate **real** Binance API keys from https://www.binance.com → API Management
4. Commit the mandate via the app (Settings → Mandate → Commit)

> ⚠️ **Never switch to live without completing the paper trading gate.** The mandate system enforces minimum trades, days, and win rate before allowing live trading.

## API Endpoint Reference

All endpoints require `Authorization: Bearer <TSAR_API_KEY>` header except health checks.

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/health` | GET | No | Basic health check |
| `/health/ready` | GET | No | Readiness probe |
| `/health/detailed` | GET | Yes | Detailed component health |
| `/` | GET | Yes | System dashboard |
| `/api/v1/trades` | GET | Yes | Trade history |
| `/api/v1/trades/stats` | GET | Yes | Trade statistics |
| `/api/v1/positions` | GET | Yes | Open positions |
| `/api/v1/pnl` | GET | Yes | P&L summary |
| `/api/v1/risk` | GET | Yes | Risk state |
| `/api/v1/kill-switch` | POST | Yes | Emergency halt |
| `/api/v1/resume` | POST | Yes | Resume trading |
| `/api/v1/mandate` | GET | Yes | Mandate status |
| `/api/v1/factors` | GET | Yes | Factor library |
| `/api/v1/strategies` | GET | Yes | Strategy performance |
| `/api/v1/regime` | GET | Yes | Market regime |
| `/api/v1/flywheel` | GET | Yes | Flywheel health |
| `/api/v1/paper/dashboard` | GET | Yes | Paper trading dashboard |

## Troubleshooting

### App shows "Disconnected" (red dot)
1. Check Render service is running: Dashboard → Logs
2. Verify URL has no trailing slash
3. Verify `TSAR_API_KEY` matches between Render env and app
4. Check `TSAR_CORS_ORIGINS` in Render — if set, it must allow your app's origin

### "401 Unauthorized" errors
- `TSAR_API_KEY` in the app doesn't match the one in Render
- Copy the exact value from Render Dashboard → Environment

### "503 API key not configured"
- `TSAR_API_KEY` is not set in Render environment
- Set it and redeploy

### Health check fails in Render
- Service may need more startup time (Render has a start period)
- Check logs for Python import errors
- Verify `Dockerfile.trading` is selected in render.yaml

### No trades appearing
- System is in paper mode — trades happen when signals trigger
- Check `/api/v1/regime` for current market regime
- Check `/api/v1/flywheel` for pipeline health
- TSAR strategy requires sufficient market data (50/200 MA periods)

### WebSocket not connecting
- The app converts `https://` → `wss://` automatically and connects to `/ws`
- **Note**: The backend currently does NOT expose a `/ws` WebSocket endpoint
- The app handles this gracefully — falls back to HTTP polling (auto-refresh)
- Real-time price streaming will be added in a future update

## Quick Verification Commands

```bash
# Replace with your actual values
RENDER_URL="https://tsar-trading.onrender.com"
TSAR_API_KEY="your-api-key-here"

# 1. Health check (no auth needed)
curl -s "$RENDER_URL/health" | python3 -m json.tool

curl -s -H "Authorization: Bearer $TSAR_API_KEY" "$RENDER_URL/api/v1/risk" | python3 -m json.tool

# 3. Check paper trading gate
curl -s -H "Authorization: Bearer $TSAR_API_KEY" "$RENDER_URL/api/v1/paper/gate" | python3 -m json.tool
```
